# Kotatsu build progress

The complete PLAN.md was read before implementation. No ancestor/repository CLAUDE.md or AGENTS.md exists. The initial MVP was developed and tested in an isolated sandbox without publishing. Publication is recorded separately below.

## Step 1
Established the Go module, three executable boundaries, shared API types, version metadata, private config-file writes, URL policy, and build/test commands. Selected the official MongoDB Go v2 driver, coder/websocket, creack/pty, x/term, Cobra and Google UUID. Chub has no matching Go guides; checked the installed package reference with go doc instead. Plain HTML/JS without CSS is the explicit UI requirement.

## Step 2
Added transactional MongoDB persistence with owner-scoped queries, UUIDs, unique token hashes, and account token registration, exchange (/me), issue, atomic rotation, listing and owner-scoped revocation. Authentication never persists raw credentials. Added bounded registration rate limiting, JSON size/schema limits, no-store responses, cross-origin mutation rejection, trusted-proxy-only forwarding, structured logs without request URLs, and a gracefully terminating HTTP entry point. Token lifecycle, persistence, permissions, and API authorization tests pass.

## Step 3
Implemented atomic one-time/reusable expiring enrollment, separate machine credentials, collision-checked seven-digit IDs, owner-only inventory, observed-IP heartbeats and 90-second offline calculation. Added the no-store, rate-limited /script endpoint with pinned Linux architecture artifacts, checksum verification, dedicated account and systemd service. Agent enrollment refuses existing state, stores private identity and rejects root execution. Tests cover concurrent single redemption, ID collision retry, account/machine/enrollment credential separation, expiry, revocation, heartbeat status and untrusted forwarded IP. Race tests/build/vet pass.

## Step 4
Added CLI registration/login/logout/whoami, token list/create/revoke/rotate, ls in text or JSON, and enrollment create/list/revoke. Login accepts hidden terminal input or stdin, not secret command-line flags. Config writes remain atomic/private. Added embedded semantic plain HTML and external JavaScript without CSS, owner-scoped inventory fields, registration/login and install-token controls. Web secrets exist only in page memory, no localStorage/cookies; untrusted values use textContent. CLI API integration tests and all race/build/vet checks pass.

## Step 5
Added authenticated outbound agent WebSockets with bounded exponential reconnect, 30-second heartbeats, server-created relay IDs and max four sessions per machine. CLI connect negotiates TERM/size, switches/restores raw terminal mode, forwards resize (SIGWINCH on Unix, polling on Windows), returns shell exit codes and supports Ctrl-] detach. Agent starts /bin/sh as its current unprivileged identity, multiplexes bounded PTY data queues and kills session process groups/descendants on disconnect. Relays have one-hour maximum and ten-minute idle bounds, token-revocation checks and metadata-only audit records. Server shutdown closes WebSockets explicitly. Race-tested real Linux PTYs for initial/resized stty dimensions, exit 7, owner isolation, CLI stream connection, identity survival across agent restart, invalid protocol frames, active token revocation and shutdown.

## Step 6
Added a non-root multistage server Dockerfile, persistent-volume loopback-bound Compose deployment with healthcheck, pinned-release allowlist serving, deterministic checksummed release packaging, uninstall script, push/PR CI and tag-publish workflow. Documented development versus production TLS, trusted edge/header/log policy, account and machine permissions, API/CLI usage, release trust, MongoDB backup and session limits. Cross-built and checksummed all five CLI and two agent archives successfully. Docker/systemd runtime validation will be reported separately; this sandbox has no Docker socket and PID 1 is not systemd.

## Step 7, security review fixes
An independent read-only review found cleanup and lifecycle gaps. Replaced process-group-only cleanup with a per-PTY subreaper supervisor whose private lifetime pipe closes even on agent death; detached setsid/double-forked children remain adopted and are stopped/killed/reaped on disconnect. Added schema-v2 machine credential revocation plus owner-authorized DELETE and CLI revoke-machine, immediately closing active links/sessions and rejecting reconnect. CLI now unwinds on SIGTERM and sends terminal EOF when piped input ends. Moved session revocation/idle checking into an independent cancellation watchdog so stalled writes cannot block enforcement. Added real PTY regressions for piped EOF, cross-owner revocation, active machine revoke/reconnect rejection, and detached-process termination. All tests pass under the race detector; build/vet pass. The restricted shared service user is not a hostile multi-tenant sandbox.

## Step 7, final verification
Added tests executing the exact rendered installer for unsupported CPU architecture and corrupted AMD64/ARM64 downloads, plus a positive path with a real checksummed Linux agent archive and real enrollment API. The positive-path harness redirects account/systemd actions into an isolated temporary root, verifies private state and hardened service contents, and restarts the installed agent twice without duplicating its identity. This is not a real systemd runtime test. Added automatic reconnect after transport drop, idle/max-session expiry, a real terminal SIGTERM restoration check, TLS/trusted-forwarding boundaries, static-release path and symlink allowlists, API secret non-disclosure and registration rate limiting tests. Tightened checksum selection to literal artifact matching and explicit installer prerequisites. Keep closing sessions tracked until audit cleanup completes so shutdown can await them. Full race tests, all executable builds and go vet pass. No push or external host actions.

## MongoDB and real Docker/systemd validation
Replaced SQLite with the official MongoDB Go v2 driver. Compose runs MongoDB 7 without authentication or published database ports, on its private network. A single-node replica set enables atomic registration, credential rotation and enrollment; unique indexes and owner-scoped queries preserve isolation. Standalone MongoDB is rejected. No automatic SQLite import is provided.

On Linux amd64 Docker, the Mongo-backed server built and passed health checks. Three containers ran real systemd as PID 1 without privileged mode, using host cgroup namespaces and a writable cgroup mount because private cgroup namespaces failed to boot on this host. The actual installer verified pinned checksums, created the restricted kotatsu account, installed an active/enabled hardened service and survived service/container restarts. Two accounts had separate inventories. Each machine passed real CLI PTY commands, resize (28x88 to 49x121), exit-code 7 and local terminal restoration. Server and MongoDB restarts preserved accounts/machines; agents reconnected. Revoked account/enrollment/machine credentials were rejected, stopped agents became offline, and the shipped purge uninstaller removed each service, binary, identity and user.

The full real-replica-set go test -count=1 -race ./... suite and go vet passed. New regressions verify registration/rotation rollback, concurrent single-use enrollment and display-ID collision retry. CI now supplies a disposable replica set instead of silently skipping database tests. Native macOS/Windows/arm64 runtime execution remains untested.


Browser QA on the Mongo-backed Docker server passed registration, token display/clear, logout/login, empty owner inventory, one-use enrollment creation/revocation/refresh and reload logout without stored secrets.
